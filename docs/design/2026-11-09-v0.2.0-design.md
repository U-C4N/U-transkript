# u-transcript max 0.2.0 — design

Approved in conversation on 2026-11-09. The next release is **0.2.0**. It replaces the 0.1.0b1
proposal, which was never committed. M9 (MKV/WebM) comes back into this release. M10 becomes
"Docs & release 0.2.0".

## 1. Goals

- The newest AI models in every provider, plus a Grok provider. Provider translation works in
  the library and, when configured, inside the MCP server.
- Faster downloads, above all through the MCP server. Three things get faster: the transfer
  itself, the wait before the first byte, and translated subtitles.
- The highest quality by default. "Medium" (at most 720p) and "low" (at most 360p) are there on
  request.
- `.mkv` and `.webm` targets (M9), so the highest quality also covers VP9 pictures and Opus
  audio.

## 3. Findings behind the plan (2026-11-09)

- Every media request opens a new TCP+TLS connection (`adapters/http.py:36`). Ranges are
  2 MiB (`core/downloads.py:24-29`), so a 1 GB file pays about 500 handshakes.
- `Downloader._advance` holds the shared lock while the progress callback runs. `_finish`
  holds it while writing and fsyncing the resume state (`adapters/downloader.py:461-470`).
  In the MCP server the callback waits for the event loop (`mcp/server.py:529`), so every
  download thread stalls during each report.
- The MCP instructions ask for `list_formats` and up to three questions before every download
  (`mcp/server.py:76-91`).
- `list_formats` and `download` each make their own player request
  (`services/download.py:153`, `:169`).
- Captions are fetched one by one (`services/download.py:279-291`).
- `Quality` is `"best" | "compat"` (`models.py:46`). The audio is always the highest bitrate
  (`core/streams.py:191-213`).
- VP9 and Opus are parsed but never chosen (`core/streams.py:42-43`). A video without AV1 at
  its largest size therefore stays at H.264 1080p in `.mp4`.
- The MCP server calls no AI provider (`mcp/server.py:5-7`). The assistant writes every
  translation itself, which is slow for long videos.
- The `gemini` adapter imported and caught httpx (`gemini.py:63`, `:93`). google-genai 3.0
  (2026-11-06) sends through httpx2 and no longer installs httpx.
- anthropic 2.0 (2026-10-21) moved to API version 2026-10-21. It is compatible with the
  adapter: the adapter sends one credential, plain dict messages and no sampling parameters.
- Model shutdowns:
  - `gpt-5-mini` shuts down on 2026-12-11;
  - `gemini-2.5-flash` is rerouted to `gemini-3.5-flash-lite` from 2026-12-01.

## 4. Milestones, in order

### M11 — Newest models and Grok

- **Grok.** A `grok` provider: `GrokTranslator`, an `OpenAITranslator` subclass on
  `https://api.x.ai/v1`. The key comes from `api_key` or `XAI_API_KEY`, never from
  `OPENAI_API_KEY`. The `grok` extra installs the openai SDK.
- **`effort` for every provider.** Lower is faster:

  | Provider | Values | Sent as |
  |---|---|---|
  | claude | low–max | `output_config.effort` |
  | openai, grok | low–xhigh | `reasoning_effort` |
  | gemini | low–high | `thinking_level` |
  | openrouter | low–high | `reasoning.effort` |

  A value the provider does not accept raises `InvalidOption`.
- **Gemini.**
  - The extra becomes `google-genai>=2.30.1,<4`; Gemini 4 Argon needs 2.30.1.
  - The adapter catches the transport errors of httpx2 and of httpx, whichever is installed.
  - The client is pinned to API v1beta, which every 2.x release used.
- **Claude.** The extra becomes `anthropic>=1.8,<3`.
- **Examples.** Examples, error texts, unit tests and live-test defaults use the newest model
  ids.
- **Acceptance.** All gates green with anthropic 2.6.0 and google-genai 3.0.0 locked. A live
  translation runs per provider key.

### M12 — Faster downloads and quality levels

- **Keep-alive.** `UrllibTransport.stream` reuses one persistent connection per worker thread
  and host.
  - A connection is reused only after its body was read to the end.
  - Redirects are followed by hand.
  - Proxies work through `set_tunnel` and `force_ipv4` through `source_address`.
- **Progress without the lock.** Progress callbacks and resume-state writes run outside the
  downloader lock. The MCP server reports the latest value from an async task instead of
  blocking the download threads.
- **Connections.** The default is measured live at 4, 6 and 8 connections (Big Buck Bunny,
  `aqz-KE-bpKQ`, 2160p). The MCP setting is `UTMAX_CONNECTIONS`.
- **Shorter wait.**
  - The streams player response of a video is kept for 5 minutes, so `list_formats` followed
    by `download` asks once.
  - Captions are fetched in parallel, still before the first media byte.
  - The MCP instructions download at once with the defaults. They call `list_formats` only
    when the user asks what is available or names a size that needs checking.
- **Quality levels.** `Quality` gains `"medium"` (≤ 720p) and `"low"` (≤ 360p).
  - When `resolution` is also given, the smaller limit wins.
  - `"low"` also takes the lowest-bitrate audio of the preferred track, and `.mp3` uses
    `-q:a 6`.
  - The MCP `quality` argument and the instructions map "medium" and "low" (in any language) to
    these values.
- **Acceptance.** MB/s before and after is recorded. `medium` gives at most 720p and `low` at
  most 360p, checked with ffprobe.

### M13 — Translation inside the MCP server

- **Settings.**
  - `UTMAX_TRANSLATOR` holds a model spec such as `gemini=gemini-3.8-flash`, checked at
    startup.
  - `UTMAX_TRANSLATOR_EFFORT` defaults to `low`, for speed.
  - Keys come from each provider's own variable.
  - Install, for example, with `uvx --from "u-transcript-max[mcp,gemini]@latest" utmax-mcp`.
- **Tools.**
  - `download(translate_to=[...])` and `save_subtitles(translate_to=...)` translate on the
    server with `Client.translate`; the engine already sends batches in parallel.
  - Several languages are translated at the same time.
  - The track title names the model, such as "Turkish (AI: grok=grok-4.7)".
- **Instructions.** They are built at startup. With a translator they say to use
  `translate_to`; without one, today's flow stays: the assistant translates.
- **Acceptance.** In-memory MCP tests with a fake translator, and one live MCP translation.

### M9 — MKV and WebM

As in `2026-10-09-high-quality-downloads-design.md` §4: a shared media model with
byte-identical MP4/MOV/M4A output, an EBML/WebM reader, codec configuration conversion, a
Matroska writer, `.mkv` and `.webm` targets, and the tests listed there.

Additions:
- The quality levels apply to every target.
- The MCP `format` argument defaults to `null`. The server then chooses `mp4` when it holds the
  best picture (size, frame rate, HDR), else `mkv`.

**Acceptance.** As in the M9 design. In addition, a 4K video without AV1 downloads through the
MCP default as `.mkv` 2160p VP9 with Opus, checked with ffprobe.

**How it was built (2026-11-09).**

*Modules*

The modules are in `core/media/`:

- `ebml.py`: the binary format and element IDs.
- `webm.py`: indexes frames without reading them; unknown-size clusters are supported and laced
  blocks are refused.
- `codecs.py`: avcC, av1C and the AudioSpecificConfig become CodecPrivate; colr, mdcv and clli
  become a Colour element.
- `model.py`: `MediaTrack`, with presentation times from the MP4 edit list. Audio priming that
  the edit list hides is dropped, and leading empty edits become a delay.
- `matroska.py`: the writer.

*The writer*

- The file is laid out as SeekHead, Info (1 ms timestamps), Tracks, Cues, then the clusters.
  The Cues come before the clusters, and their positions are written with fixed 8-byte widths,
  so every size is known before any offset is.
- A cluster starts at every video keyframe and lasts at most 5 seconds.
- Subtitles are S_TEXT/UTF8 blocks with a BlockDuration.
- The output is a `MuxPlan`, which the existing executor writes.

*Decisions*

- The MP4/MOV/M4A muxer was left as it is, because `.mp4` takes only MP4 sources. Its output is
  byte-identical by construction, and the shared model feeds only the Matroska writer.
- `.webm` writes subtitles as sidecar files, and gets none unless they are asked for.

*Checked with ffmpeg 9.0.2*

- Real streams of `aqz-KE-bpKQ` decoded without errors: VP9+Opus as `.webm` and `.mkv` (with
  subtitles, which ffmpeg read back), AV1+AAC and H.264+AAC as `.mkv`.
- lavfi VP9+Opus made by ffmpeg passed the same way.
- The CI ffmpeg job runs these checks as tests (`tests/unit/media/test_ffmpeg.py`).

### M10 — Docs & release 0.2.0

- **Docs.**
  - CHANGELOG (the five GitHub release notes, then 0.2.0) and CONTRIBUTING.
  - `uv sync --all-extras` in `CLAUDE.md`.
  - The README: providers, quality levels, the MCP translator, MKV/WebM, the legal/ToS note and
    the ASCII diagram.
  - The milestone table of the main design.
- **CI.**
  - A `lowest-direct` job that runs its tests with `uv run --no-sync`, because a plain
    `uv run` re-resolves the lock.
  - A lock refresh, and Python 3.15 in the CI matrix and the classifiers.
  - `release.yml` publishes only a CI-green commit on main.
  - SHA-pinned actions and Dependabot.
- **Release.** Version 0.2.0 with the `4 - Beta` classifier. The live suite and the release
  checklist run, then the tag and the publish happen when the maintainer says so.

## 5. Not in 0.2.0

- Gemini 4 Carbon, which is not in the public API.
- Cheaper model variants in the docs.
- The rest of the 2026-10-09 "Not now" list: choosing the dubbed audio language, HLS
  "premium" formats, a JavaScript runtime, and PO token minting.

## 6. Process

- One local branch per milestone.
- Every change comes with its tests and a CHANGELOG line, and the gates must be green.
- Nothing is pushed, merged into `main`, tagged or published without the maintainer's explicit
  approval (main design §12, item 4).
